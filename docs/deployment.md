# Deployment guide

The repository contains one environment named `example`. Duplicate and rename the environment only after the first deployment pattern has been tested.

## Bootstrap

```bash
cd infrastructure/Tofu/bootstrap
tofu init
tofu plan -var-file=environments/example.tfvars
tofu apply -var-file=environments/example.tfvars
```

After the first apply, update the backend files using the bootstrap outputs. Moving bootstrap state to the remote backend is optional but recommended for team use.

## Main infrastructure

```bash
cd infrastructure/Tofu
export AWS_PROFILE=example
export AWS_REGION=eu-west-2
export EXPECTED_ACCOUNT_ID=111122223333

./scripts/deploy.sh fmt
./scripts/deploy.sh init
./scripts/deploy.sh validate
./scripts/deploy.sh plan
./scripts/deploy.sh apply
```

The apply action uses the saved plan generated by the plan action.

## Enabling Kubernetes platform resources

The sample sets `enable_kubernetes_platform = false`. This avoids attempting Kubernetes and Helm provider operations before private API connectivity is available.

A common two-stage process is:

1. Deploy AWS infrastructure with Kubernetes platform resources disabled.
2. Establish connectivity to the private EKS API.
3. Set `enable_kubernetes_platform = true`.
4. Run a new plan and apply.

## Destroying resources

There is intentionally no destroy action in the helper script. Destruction of a platform stack is high impact and should be performed explicitly after checking retained data, state, backups, termination protection, and S3 bucket contents.
